## What I saw

### tmux (master, changes from 3.7c toward 3.8, unreleased)

Source: https://raw.githubusercontent.com/tmux/tmux/master/CHANGES

- Hooks are now internal events with payloads. Control mode gets
  "monitors": `set-hook -B` checks a format every second and fires a hook
  when it changes or becomes true.
- OSC 133 sequences now trigger events: `pane-command-started`,
  `pane-command-finished`, `pane-shell-prompt`.
- New formats: `pane_last_output_time`, `pane_output_generation`,
  `hook_fire_count`, `hook_fire_time`.
- `wait-for -E` waits for hooks, notifications, or user events.
- Many control-mode fixes: bounded buffered replies, no hang on exit with
  queued pty data, stuck clients cannot block server exit.
- `capture-pane -I` records the time each line entered history.

The box runs tmux 3.4. None of this is available today. hive watches
panes by polling `capture-pane` and `display-message` (src/tmux.ts). The
3.8 event model is a direct fit for that job once it ships.

### jj v0.46.0 (latest release)

Source: https://github.com/jj-vcs/jj/releases

- `jj workspace add --colocate` can create a Git worktree per workspace.
  `jj workspace remove` removes a workspace and its directory from disk,
  snapshotting the working copy first.
- Breaking: minimum git is now 2.42.0. The box has git 2.43.0, so we are
  clear.
- Breaking: `jj undo`/`redo` refuse operations from another workspace
  unless `--allow-cross-workspace` is passed.
- `jj git push` can push to multiple remotes at once.

The box runs jj 0.44.0. Our lane discipline (AGENTS.md) uses jj
workspaces per lane. `jj workspace remove` could replace manual lane
cleanup. The cross-workspace undo refusal matters if any orchestrator
code ever touches another lane's repo state.
