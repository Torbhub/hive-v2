## What I saw

### Kimi Code 2.3.1 (latest; the box already runs it)

Source: https://github.com/MoonshotAI/kimi-code/releases

- Fix: sessions occasionally remaining occupied after an application crash
  on macOS and Linux. hive spawns long-lived kimi sessions for its agents.
  A crashed agent that wedges its session is exactly this failure.
- New: after a retry, kimi offers to take over a session that is still in
  use. That offer is an interactive prompt. An automated pane cannot answer
  it on its own.
- New: `KIMI_CODE_SESSION_LOCK=0` turns the session lock off completely.
- Show the holding client's name in session-in-use errors.

Older releases on the same page (2.3.0, 2.2.x, 2.x) were covered on
2026-10-22. The deslop skill name fix from that day's note has landed
(PR #41 merged), so the 2.3.0 qualified-skill-name item is closed.

### tmux (master, changes from 3.7c toward 3.8, unreleased)

Source: https://raw.githubusercontent.com/tmux/tmux/master/CHANGES

Still no "CHANGES FROM 3.8" section, so 3.8 has not shipped. The carried
lead stays blocked. The box runs tmux 3.4.

Beyond the event model noted on 2026-10-21 (hooks as internal events,
OSC 133 `pane-command-finished`, `set-hook -B` monitors), the same section
also lists:

- Layout strings move to a JSON subset format that includes floating
  panes. Control-mode clients get old layouts unless they set the
  `new-layouts` flag.
- Floating panes get a large feature set: modal panes (`new-pane -O`),
  `new-pane -W` waits for the pane command to exit, `break-pane` can
  float a tiled pane.

When 3.8 ships, the JSON layout strings matter for hive on top of the
events: `src/tmux.ts` verifies pane identity before every kill or type.
A machine-readable layout beats parsing display strings.

## Candidate experiments (ranked by expected value)

1. **Set `KIMI_CODE_SESSION_LOCK=0` where hive spawns agent sessions.**
   kimi 2.3.1 fixes crash-wedged sessions, but its repair path is an
   interactive take-over prompt that an automated pane cannot answer.
   hive manages its own sessions and knows they are unique, so the lock
   buys nothing and the prompt can wedge the daily loop. One-line env
   change in the spawn path, verifiable on the box. Risk: two clients in
   one session stop being guarded; hive's lane rules already forbid that.
2. **Prototype tmux 3.8 event hooks for pane watching** (carried, still
   blocked on 3.8 shipping). Add JSON layout strings to the same

   machine-readable source. Both land in one experiment when 3.8 exists.
