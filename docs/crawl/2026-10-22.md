## What I saw

### Kimi Code 2.3.0 (latest; the box already runs it)

Source: https://github.com/MoonshotAI/kimi-code/releases

- **Breaking for hive:** plugin skills are now listed and invoked only by
  their qualified `<pluginId>:<skillName>` name. Invoking a plugin skill by
  its bare name no longer works. `roles/deslop-reviewer.md:17` tells the
  reviewer to hunt slop "with the deslop skill". There is no project or
  user skill named `deslop` — the only one is the plugin
  `cursor-team-kit:deslop` (checked `skills/` and
  `~/.agents/skills/`). A deslop reviewer following the role today cannot
  invoke the skill by the name the role gives.
- `[permission] dangerous_command_guard = false` now turns off every
  built-in confirmation guard, including sensitive-file and git
  control-path guards, not only the dangerous-command one. If the box
  config sets this flag, its meaning quietly widened.
- Hooks such as `PreToolUse` and `Stop` now run in the session's project
  directory instead of the server's start directory, matching the docs.
- Remote Control streaming limit raised from 10 MiB to 100 MiB.
- Confirmation dialog on model switch in a session with history, shown
  only when enabled by cloud configuration.

### Kimi Code 2.2.0

Source: same page.

- Tower mode: deterministic orchestration with TowerRebase, LLM-free
  status, goal/tower mutual exclusion, workspace protection. This overlaps
  with hive's own job. Worth knowing, not a lane-sized experiment.
- The agent's in-turn wait for background tasks is capped at 90 seconds.
- Opt-in NotifyUser progress updates
  (`KIMI_CODE_EXPERIMENTAL_NOTIFY_USER=1`).
